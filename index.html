Inference Infra

Inference infra for TikTok Feed Recommendation — the serving path that has to return a ranked feed in milliseconds, at the traffic a global feed generates.

What I worked on

  • Memory. Allocation and layout on the inference hot path: reuse instead of churn, so a host holds more concurrent requests at the same footprint.
  • Scheduling. Batching and request dispatch tuned for tail latency under bursty QPS, rather than for average-case throughput alone.
  • Measurement. Latency percentiles and throughput measured end to end on production traffic shapes, not microbenchmarks.

Why it is hard

Recommendation serving is latency-bound, not FLOP-bound: the model is small next to an LLM, but the request rate is enormous and the budget per request is tiny. Most of the win lives in memory behaviour and scheduling, not in the math.

Where I worked on inference optimization, developing and optimizing kernels for low-latency, high-throughput inference in MLA-based LLMs and integrating them into vLLM.
vLLMTritonLLM

Attention kernels for MLA-based LLMs, and the plumbing that puts them on a real serving path — vLLM.

What I worked on

  • Kernels. Triton kernels for MLA decode: tiling, scheduling of the inner loops, and access patterns over the latent KV cache.
  • Bandwidth. Decode is memory-bound, so the work went into moving less — keeping the latent cache compact and the reads coalesced.
  • Integration. Wired in as a vLLM attention backend, numerics checked against the reference path, then benchmarked for latency and throughput.

Why MLA

MLA compresses the KV cache into a latent projection, which is what makes long-context decode affordable — but only if the kernel reading that latent form is written for it. A generic attention kernel gives the memory saving back at runtime.
